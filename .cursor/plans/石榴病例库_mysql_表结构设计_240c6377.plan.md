## 全局约定

- 引擎/字符集：`InnoDB` + `utf8mb4_0900_ai_ci`，行格式 `DYNAMIC`。
- 主键：所有表 `id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY`；面向外部稳定标识用 `xxx_uid CHAR(32)`（UUIDv7，`UNIQUE`），避免直接暴露自增 id。
- 通用字段（每表必带）：`created_at DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3)`、`updated_at DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)`、`created_by BIGINT NULL`、`updated_by BIGINT NULL`；业务实体表加 `deleted_at DATETIME(3) NULL`（软删），字典/审计/日志表不软删。
- 外键：业务主线表之间显式 `FOREIGN KEY` + `ON DELETE RESTRICT / ON UPDATE CASCADE`；审计/日志/索引投影表只加普通索引，不加 FK，避免锁竞争。
- 枚举：高频、稳定、跨表统一的小集合（screening_status、required_level、modality 等）用 MySQL `ENUM`；业务可扩展、需要前端配置的用「字典表 + code 字符串」。
- JSON：仅在以下场景使用：文档 OCR `field_bbox_map`、CRF `options`、`yaby_snapshot.payload`、`audit_log.diff`、`upload_job.extraction_payload`。检索维度始终落到结构化列。
- 软删除字段统一规则：`deleted_at IS NULL` 表示有效；唯一索引使用 `(business_key, deleted_at)` 复合，避免软删后无法重建。
- 「可枚举但需扩展」的取值用三张主码表：`code_set`、`code_value`、`code_value_alias`，业务表中存 `code` 字符串。

## 1. 核心业务表（约 25 张）

身份与就诊：

- `patient`：内部唯一标识，含姓名（建议存哈希 + 显式 `name_cipher`）、性别、出生年、`mrn_primary`，唯一索引 `(mrn_primary, deleted_at)`，普通索引 `(birth_year, sex)`。
- `patient_mrn`：一患多就诊号 1:N，唯一索引 `(source_org_code, mrn, deleted_at)`。
- `encounter`：门诊/住院/急诊/随访，外键 `patient_id`，索引 `(patient_id, admit_date)`、`(encounter_type, admit_date)`。

文档与证据（L0/L1）：

- `document`：原始资料（IMG/PDF/AUDIO/VIDEO/TEXT），`file_uri`、`file_hash` 唯一索引去重，`modality ENUM`、`doc_type` 用字典 code，外键 `patient_id / encounter_id / event_id`（后两者可空）。
- `document_page`：分页位图/页面级 OCR 文本与 hash，外键 `document_id`。
- `document_ocr`：整篇 OCR/ASR 文本（`MEDIUMTEXT`）+ `field_bbox_map JSON`。
- `evidence_anchor`：字段定位（page、bbox、time_offset、excerpt），与 `document` 1:N，可被多个字段引用。

病例（聚合根）：

- `case`：业务上的「病例」聚合（对应原型 `CaseSummary/CaseDetail`）。包含 `patient_id`、`disease_profile_id`、`crf_template_id`、`crf_template_version`、`primary_site_code`、`tumor_type`、`stage_label`、`line_of_therapy`、`current_regimen_label`、`screening_status ENUM`、`ecog`、`has_liver_risk`、`crf_completion_rate DECIMAL(5,4)`、`crf_blocking_missing_count`、`last_updated_at`；唯一索引 `(patient_id, disease_profile_id, deleted_at)`；普通索引 `(disease_profile_id, screening_status)`、`(crf_template_id, crf_completion_rate)`。

L2 临床事实（每张都挂 `case_id` + `event_id NULL`）：

- `diagnosis`（含 ICD-10、原发部位、组织学）
- `stage`（AJCC 体系、`tnm_t/n/m`、`ajcc_stage`、`stage_kind ENUM('clinical','pathologic')`）
- `molecular_test` + `molecular_result`
- `biomarker_result`（PD-L1/MSI/TMB/HER2/CPS）
- `line_of_therapy`（`line_no`、起止）
- `regimen`（`regimen_name_std`、`regimen_type` code）
- `drug_exposure`（外键 `regimen_id`，`drug_generic`、`drug_class` code、起止）
- `dose_change`（外键 `drug_exposure_id`，`change_type ENUM`、`reason` code）
- `lab_panel` + `lab_result`（含 `test_name_std`、`value`、`unit`、`ref_low/high`、`is_abnormal`、`ctcae_grade`），`lab_result` 索引 `(case_id, test_name_std, collection_date)`
- `imaging_study` + `imaging_report`
- `pathology_report`
- `procedure`（手术/放疗/介入；放疗细节用 `radiotherapy_detail` 1:1 扩展）
- `adverse_event`（CTCAE term/grade、起止、归因）
- `vital_signs`（ECOG/体重/身高）
- `comorbidity`
- `infection_status`（HBV/HCV/HIV）

时间线（L3）：

- `clinical_event`：统一事件锚点，`event_type` code、`event_date`、`date_source ENUM('entry','collect','report','infer')`、`is_important`。
- `event_link`：`(event_id, target_table, target_id)` 多对多，加 `(target_table, target_id)` 普通索引。

CRF 配置化（L4）：

- `disease_profile`：瘤种/瘤种组（`group_code`、`group_name`、`tumor_code`、`tumor_name`、`default_template_id`、`enabled`），唯一 `(group_code, tumor_code)`。
- `crf_template`：`disease_profile_id`、`version`、`status ENUM('draft','active','archived')`、`title`，唯一 `(disease_profile_id, version)`。同 profile 仅允许 1 条 active：`UNIQUE ((disease_profile_id, IF(status='active',1,NULL)))`。
- `crf_section`：自引用 `parent_id`、`level`、`sort_order`、`title`、`code`。
- `crf_field`：核心配置，含 `field_code`（唯一 `(template_id, field_code)`）、`path`（冗余字符串）、`label`、`data_type ENUM('text','number','date','category','boolean','unknown')`、`required_level ENUM('blocking','recommended','optional')`、`unit`、`format`、`source`、`description`、`repeatable`、`searchable`、`governance_status`、`options JSON`。
- `crf_field_mapping`：CRF 字段 → 通用主干字段，`canonical_entity` + `canonical_field` + `mapping_type ENUM('direct','normalize','derive','aggregate')` + `transform_rule TEXT`。
- `case_crf_value`（按数据类型拆列）：
  - `case_id` + `template_id` + `field_code` + `repeat_idx INT DEFAULT 0`
  - `value_text VARCHAR(1024)`、`value_number DECIMAL(20,6)`、`value_date DATE`、`value_datetime DATETIME(3)`、`value_bool TINYINT(1)`、`value_code VARCHAR(64)`、`value_json JSON`、`value_unit VARCHAR(32)`
  - `status ENUM('filled','missing','conflict','not_applicable')`
  - `confidence ENUM('verified','ai_high','ai_medium','missing','conflict')`
  - `evidence_id BIGINT NULL`、`event_id BIGINT NULL`
  - 唯一 `(case_id, template_id, field_code, repeat_idx, deleted_at)`
  - 检索索引 `(template_id, field_code, value_code)`、`(template_id, field_code, value_number)`、`(template_id, field_code, value_date)`、`(case_id, status)`
  - 生成列 `is_filled TINYINT GENERATED ALWAYS AS (status='filled') STORED` 并加索引

筛查与任务（L4）：

- `yaby_snapshot`：`case_id`、`snapshot_uid`、`snapshot_version`、`min_fields_json JSON`、`core_completion_rate`、`crf_completion_rate`、`status ENUM('not_ready','partial','ready')`、`computed_at`。
- `screening_project`：研究/筛查项目字典。
- `case_screening_status`：病例 × 项目 入选状态历史。
- `completeness_task`：补录/冲突任务，含 `case_id`、`type ENUM('missing_field','conflict_review','governance')`、`scope ENUM('canonical','crf','governance')`、`template_id`、`field_code`、`field_path`、`owner_user_id`、`due_at`、`is_blocking`、`is_completed`、`completed_at`。
- `task_conflict_entry`：冲突任务的多源对照行。

随访：

- `follow_up_plan`：随访计划（频率、下次随访日期、负责人）。
- `follow_up_record`：单次随访记录（方式：电话/门诊/线上、内容、关联 event_id、附件 document_id）。

上传与抽取：

- `upload_job`：用户上传任务（`source ENUM`、`stage ENUM('queued','processing','extracted','needs_review')`、`patient_id`、`document_id`、`description`），`extraction_payload JSON` 存 AI 原始结果。
- `extraction_detail`：审核行（`template_id` + `field_code` + `value` + `confidence` + `change_type ENUM` + `existing_field_id`）。
- `upload_review_decision`：人工决策日志（accept_new/keep_old/mark_conflict）。

用户、组织、权限：

- `user`：账号（用户名/手机号/邮箱、密码哈希、状态、最后登录），唯一 `(username)`、`(phone)`、`(email)`。
- `role`、`permission`、`user_role`、`role_permission`。
- `case_acl`：病例级权限（`case_id` + `user_id|role_id`），覆盖默认 RBAC。

检索投影（推荐保留口子）：

- `case_search_index`：跨瘤种统一检索投影（一行一病例），冗余通用主干关键字段。专病检索仍走 `case_crf_value`。

## 2. 字典 / 码表（统一 3 张）

- `code_set`、`code_value`（唯一 `(code_set_id, code)`）、`code_value_alias`（用于 OCR 归一化）。
- 覆盖：`DocType / DrugClass / EventType / ChangeReason / Comorbidity / Tag / CTCAE / RECIST / AJCC / PHIClass / TumorGroup / RegimenType`。

## 3. 关系 / 多对多表

- `case_tag`、`case_disease_group`、`event_link`、`document_field_link`、`case_template_history`、`user_role`、`role_permission`、`case_acl`。

## 4. 审计 / 日志表（不软删，可分表/归档）

- `audit_log`（`action ENUM('VIEW','EXPORT','EDIT','DELETE','LOGIN')` + `target_table` + `target_id` + `actor_user_id` + `request_id` + `ip` + `user_agent` + `diff JSON`）。
- `field_change_log`（CRF/主干字段值变更前后值 + 来源 evidence_id）。
- `export_log`（脱敏导出记录）。
- `deid_mapping`（脱敏映射，建议物理隔离）。
- `phi_access_log`（PHI 字段访问审计）。

## 5. 输出物

- `doc/db/shiliu_schema.sql`：单一 SQL 文件，按上述分组分块，含建表、字段 `COMMENT`、关键索引和外键。
- `doc/db/seed_codesets.sql`：常用码表初始化。
- SQL 文件头部注释段：命名规范、软删除策略、JSON 用法、与原型字段映射说明。

## 6. 当前需求中需要补充确认的疑点（SQL 中按合理默认 + TODO 注释先行落地）

1. PHI 加密：`patient.name`、`patient_mrn.mrn` 是否需要应用层加密列？默认明文 + `name_pinyin` 辅助检索。
2. 就诊号唯一性：默认 `(source_org_code, mrn, deleted_at)` 唯一，便于后期接外院 MRN。
3. CRF 模板"启用唯一"：默认同一 profile 下只允许 1 条 active，旧版本自动归档为 archived。
4. YABY 快照频率：默认按需触发 + 版本号递增；DB 仅存储，重算由应用层做。
5. 事件 ↔ L2 事实：默认 L2 表存可空 `event_id` + 保留 `event_link` 关系表（一事实多事件）。
6. 文件存储：`document` 默认包含 `file_size`、`mime_type`、`storage_provider`。
7. CRF 已填判定：默认用生成列 `is_filled` 加索引。
8. 审计分区：当前不分区；如预期日志量很大，后续 `audit_log`、`field_change_log` 改月分区。
9. 中文全文检索：默认对 `document_ocr.full_text`、`imaging_report.impression`、`pathology_report.path_dx` 建 `FULLTEXT` ngram 索引。
10. 立项书 / 合作协议中如有"病例评审、留言、知识图谱、AI 助手对话"等额外能力，当前 SQL 不包含，请补充。

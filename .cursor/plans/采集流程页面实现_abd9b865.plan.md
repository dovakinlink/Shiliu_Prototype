# 采集流程高保真页面实现计划

## 目标流程

```mermaid
flowchart LR
    A[收件箱FAB] --> B[选择采集方式]
    B --> C[采集模拟页]
    C --> D[填写采集表单]
    D --> E[AI处理动效页]
    E --> F[结构化结果预览页]
    F --> G[人工确认页]
    G --> H[回到收件箱]
```

完整路径：收件箱 → SourcePickerSheet → `/capture/:source` → UploadComposerSheet → `/processing/:jobId` → `/extraction/:jobId` → `/upload-review/:jobId` → pop 回收件箱

---

## 一、新增文件

### 1. 采集模拟页 — `lib/features/intake/presentation/capture_simulation_page.dart`

接收 `UploadSource` 参数，根据来源显示不同模拟 UI：

- **camera**：深色背景模拟取景器 + 白色虚线矩形「文档检测框」+ 底部圆形快门按钮；点击后切换为「拍摄预览」态（显示一张静态病理报告占位图 + 「重拍 / 使用照片」双按钮）
- **pdf**：模拟文件管理器风格——顶部搜索栏 + 3-4 个假文件行（PDF 图标 + 文件名 + 大小 + 日期）；点击某行后该行高亮带勾 + 底部出现「已选 1 个文件」确认栏
- **voice**：居中圆形录制按钮 + 上方波形占位（`CustomPaint` 画正弦波并用 `AnimationController` 横移）+ 计时器文本 `00:12`；点击停止后显示「录音完成」+ 模拟转写文本预览卡片
- **gallery**：3 列 `GridView` 显示 12 个彩色占位方块（`Container` + 渐变色模拟照片缩略图）；点击切换选中态（角标勾选）；底部栏「已选 N 张」

所有模式完成后调用同一回调：弹出现有 `UploadComposerSheet`（传入 `source` + `cases`）。**关键改动**：`UploadComposerSheet` 提交后不再仅 pop，而是先 `createUpload` 拿到 `jobId`，然后 `context.push('/processing/$jobId')`。

使用 `ConsumerStatefulWidget`；依赖 `intakeCaseOptionsProvider` 获取病例列表。

### 2. AI 处理动效页 — `lib/features/intake/presentation/processing_page.dart`

接收 `jobId`，从 `mockAppStoreProvider` 读取 `UploadJob`。

**UI 结构**（自上而下）：
- AppBar：「AI 处理中」+ 无返回按钮（`automaticallyImplyLeading: false`）
- 顶部区域：文档图标 + 文档类型 + 患者名
- 中部：线性进度条 `LinearProgressIndicator`（`AnimationController` 驱动 0→1，总时长 4 秒）
- 步骤列表（5 步）：
  1. 文档识别（OCR / ASR）
  2. 医学实体抽取
  3. 结构化字段映射
  4. 置信度评估
  5. 冲突检测

每步用 `AnimatedSwitcher` + `Icon` 切换：`○ 等待` → `◎ 进行中`（旋转 loading）→ `✓ 完成`（绿色勾）。步骤按时间间隔依次触发（800ms 一步）。

**Mock 联动**：动画期间分 2 次调用 `advanceUpload`（queued→processing→extracted），最后一次加 `pendingReviewFields`。

动画结束后延迟 500ms，自动 `context.pushReplacement('/extraction/$jobId')`。

### 3. 结构化结果预览页 — `lib/features/intake/presentation/extraction_result_page.dart`

接收 `jobId`，从 store 读取处于 `extracted` / `needsReview` 阶段的 `UploadJob`。

**UI 结构**：
- AppBar：「抽取结果」
- 顶部卡片：模拟文档预览区（`Container` 带浅灰背景 + 文档类型图标 + 「原文档预览」文字 + 2-3 个彩色高亮矩形条模拟标注区域）
- 统计摘要行：「识别 N 个字段 · M 项高置信 · K 项需确认」，使用 `Row` + 彩色圆点
- 字段列表：复用 `extractedHighlights` 渲染每项，每行左侧 AI 图标 + 字段名值 + 右侧置信徽标（`StatusBadge`：高置信→success，需复核→warning）
- 底部固定栏：若有 `pendingReviewFields` 显示「N 项需人工确认」+ `FilledButton`「进入人工确认」跳转 `/upload-review/$jobId`；否则显示「全部高置信」+ 「直接入库」按钮

## 二、修改现有文件

### 4. 路由注册 — [app_router.dart](lib/app/app_router.dart)

在全屏栈路由区新增 3 条：

```dart
GoRoute(
  path: '/capture/:source',
  builder: (context, state) {
    final source = UploadSource.values.byName(state.pathParameters['source']!);
    return CaptureSimulationPage(source: source);
  },
),
GoRoute(
  path: '/processing/:jobId',
  builder: (context, state) => ProcessingPage(jobId: state.pathParameters['jobId']!),
),
GoRoute(
  path: '/extraction/:jobId',
  builder: (context, state) => ExtractionResultPage(jobId: state.pathParameters['jobId']!),
),
```

### 5. 入口流程改造 — [inbox_page.dart](lib/features/inbox/presentation/inbox_page.dart)

修改 `_SourcePickerSheet` 的 `_SourceOptionCard.onTap`：不再直接弹 `UploadComposerSheet`，改为 `Navigator.pop` 关闭 sheet 后 `context.push('/capture/${source.name}')`。

### 6. 表单提交流程改造 — [intake_page.dart](lib/features/intake/presentation/intake_page.dart)

修改 `UploadComposerSheet` 的提交逻辑：`createUpload` 返回 `UploadJob` 后，pop sheet 并 `context.push('/processing/${job.id}')`。需要在 `_UploadComposerSheetState` 中拿到外层 `GoRouter` context（通过构造传入或用 `rootNavigator`）。

### 7. Mock Store 增强 — [mock_app_store.dart](lib/data/mock/mock_app_store.dart)

- `createUpload` 返回值已是 `UploadJob`（当前实现已有），确认无需改动
- 新增 `advanceToNeedsReview(String jobId)`：一步将 job 从任意阶段推进到 `needsReview`（processing 页动画结束时调用），同时填充 `extractedHighlights` 和 `pendingReviewFields`
- 为每种 `documentType` 预设合理的 mock highlights/fields 映射表

### 8. 人工确认页增强 — [upload_review_page.dart](lib/features/intake/presentation/upload_review_page.dart)

- 在 `_ReviewFieldTile` 中增加「查看原文」`TextButton`，点击弹出 bottom sheet 显示模拟的 `EvidenceAnchor`（定位文本 + 摘录高亮），与 `EvidenceCard` 风格一致
- `_submit` 成功后增加一个 0.8 秒的成功动画（绿色勾 + 「已入库」文字），然后 pop 回收件箱
- 在底部栏 `_BottomBar` 增加进度感：已确认字段的圆点由灰变绿

### 9. UploadJob 模型扩展 — [upload_job.dart](lib/features/intake/domain/upload_job.dart)

新增可选字段 `extractionDetails`（`List<ExtractionDetail>`），用于结构化结果预览页渲染：

```dart
class ExtractionDetail {
  const ExtractionDetail({
    required this.fieldName,
    required this.value,
    required this.confidence, // FieldConfidence
    this.sourceLocator,       // 例如 '第 1 页 · 框 02'
  });
  // ...
}
```

`copyWith` 增加对应参数；`advanceToNeedsReview` 时填充此字段。

## 四、设计规范备忘

- 所有新页面遵循现有 `AppSpacing.page` 边距、`AppSpacing.radiusLg` 卡片圆角
- 颜色使用 `AppPalette` 语义色（success/warning/pending/conflict），支持深色模式
- 动画使用 `SingleTickerProviderStateMixin` + `AnimationController`，不引入第三方动画库
- 状态管理统一走 `flutter_riverpod`，Mock 数据通过 `mockAppStoreProvider` 集中管理
